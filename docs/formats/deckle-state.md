# Compatible-client state v1

This specification, its schema, `fixtures/state` and `tools/validate-state-fixtures.py` are MIT licensed; see `fixtures/state/LICENSE`.

This additive filesystem contract is independent of legacy returns. A compatible client writes only `.deckle-state/v1/<writer-uuid>/<subject-key>.json` for its own installation UUID; peer snapshots are read-only. No accounts or service are required. Never infer removal from a missing file. Only a tombstone removes a register value.

## Identity and canonical bytes

The `subject` is either fresh (paper UUID, edition UUID, manifest SHA256) or legacy (calendar date, manifest SHA256). UUIDs are lowercase hyphenated ASCII, hashes lowercase 64-digit hexadecimal, dates Gregorian `YYYY-MM-DD` (years 0001–9999). The subject key is SHA256 of UTF8 JSON array bytes with no whitespace: `["fresh","<paper_id>","<edition_id>","<manifest_sha256>"]` or `["legacy","<date>","<manifest_sha256>"]`. There is no trailing newline, escaping, or normalization. All tuple members are validated ASCII. Fresh and legacy subjects never alias, and changing the manifest changes the key. Fixtures pin bytes and keys in `subjects.json`.

## Operations and ownership

Each snapshot holds at most one operation per typed logical key, all authored by `writer_id`. The positive `revision` increases on each publication. A dot is `(writer_id,counter)`; counters are per writer **per subject**, positive and at most 9007199254740991. Distinct edits cannot reuse a dot, even on different keys. Context is a map of observed positive counters with at most 32 writers. An operation's own context counter must be less than its dot counter. Omitted entries mean zero. Values, dots, contexts, and display timestamps are immutable across republication. Unrelated edits must not upgrade an old operation's context. A later local edit must observe the retained previous local edit it replaces. Across known increasing revisions, every newly introduced dot must exceed the previous snapshot's writer/subject high-water counter and its context must include all dots and captured causal context in that previous snapshot. Retained operations keep their original contexts.

A key is last-location, story-position, stable mark UUID, crossword puzzle/row/column, or whole ladder puzzle. Key and value kinds must agree. Story-position anchor story must match its key, mark UUID must match its key. Clears use JSON `null` value. No writable puzzle-completion flag exists. Anchors bind story ID, exact listed body SHA256, canonical UTF16 offset and quote context. Marks bind UUID, story/body, quote/note, and a positive UTF16 range or `null` for legacy unknown range; never invent a legacy range or deduplicate distinct UUIDs by quote. Validate ranges/offsets against verified text and composed-character boundaries at use time. Validate body hashes against the subject's verified manifest before applying values; decoding alone cannot perform that external binding.

## Causal merge

Validate every snapshot wholly before advancing context. Reject mixed subjects, unequal operations sharing a dot, duplicate keys/dots, owner mismatches, and causal cycles. An operation supersedes another operation **of the same key** iff its immutable context includes the other's dot. Keep every nondominated operation; timestamps never select winners. Presentation may coalesce equal values, but must preserve all causal dots. Explicit resolution emits a fresh operation observing all alternatives. Observed context includes all validated operation dots and contexts, including superseded operations. Delivery order, duplicates and stale deliveries cannot resurrect an observed tombstone. `lineage-counter-rollback.json` is structurally valid alone but invalid after `lineage-old.json`: an earlier peer clear must not erase an operation introduced later with a rolled-back counter. `lineage-new-valid.json` advances the counter/context and remains concurrent with `lineage-peer-clear.json`. Repeated historical revisions may be merged for verification; persistence must reject an equal revision with differing canonical payload, ignore older revisions after caching the last-good snapshot, and check that replacement local operations dominate removed local operations.

Allocate counters, capture observed context, mutate the own snapshot, and persist the pending journal in **one atomic transaction**. Checkpoint updates to last-location and story-position are one atomic batch. Reject the whole edit before mutation if any limit fails. Pending journals and last-good peer snapshots are private persistence concerns; this contract does not supply a storage engine.

## Bounds and decoding

Reject input over 2097152 bytes before decoding. At most 10000 registers per snapshot, 32 writers per merged subject (including context-only writers), 32 context entries per operation, 16384 UTF8 bytes per quote/note, and 100 Unicode scalar characters per nonempty display name. Rows/columns are 0–999, ladder has at most 1000 uppercase ASCII words of 1–128 letters. Safe story/puzzle identifiers match `[A-Za-z0-9][A-Za-z0-9_-]{0,127}`. Range sums must not exceed 9007199254740991. Timestamps use RFC3339 (including lowercase `t`/`z`), Gregorian valid dates, timezone required, and are display-only; preserve the original spelling. Unknown fields and unsupported versions are rejected. Encoding uses sorted object keys, compact JSON, unescaped slashes, no trailing newline; array register order is retained. JSON Schema describes structure; the semantic verifier also checks byte limits, key/value relationships, owner/context rules, and dot consistency. Require integer JSON tokens, not booleans or fractional numbers.

Limit exhaustion is an explicit error: pause merging/publication while preserving private pending work and last-good presentation. Never evict a writer, operation or tombstone; v1 has no retirement, reset, or garbage collection. Corrupt peers are reported/skipped by the caller without deleting their bytes or blocking local edits. File access must reject unsafe paths, symlinks, nonregular files and oversize data before reading. These filesystem checks are outside this portable codec.
