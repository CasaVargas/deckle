# M5: Ship — Implementation Plan

**Goal:** Someone who is not the owner can download Deckle for Mac or Windows, install it, and
send a book, knowing what it does, what it sends over the network, and whose work it rests on.

**Spec:** design §12 M5 (GUI polish, installers, README with the research write-up, first tagged
release; macOS Developer ID signed and notarized; Windows unsigned with a SmartScreen note; no
auto-updater, a version and a Releases link instead), §3 (Wiktionary attribution in-app).

## Facts

- This Mac has an *Apple Development* identity only, no *Developer ID Application*; notarization
  credentials are not set up. Signing and notarization need the owner (certificate from the
  Apple Developer account, then repository secrets).
- Tauri 2 bundles `.app`/`.dmg` (macOS), NSIS `.exe` and `.msi` (Windows). `tauri-action` builds
  them in CI and attaches them to a GitHub release. Signing switches on when
  `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY` and the notarization
  trio (`APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID`) are present; without them the `.app` is
  ad-hoc signed and Gatekeeper asks the user to approve it once.
- Links in the webview (`<a target="_blank">`) do not open the browser in Tauri 2; that needs
  `tauri-plugin-opener`.

## Tasks (commit per task)

1. **GUI polish.** `tauri-plugin-opener` for external links (Previewer download, Releases,
   licenses). Settings drawer gets an **About** section: version, "Check for a newer version"
   (opens Releases; no updater, no phone-home), what goes over the network and when, licenses and
   credits (GPL-3.0-or-later; Wiktionary via kaikki.org CC BY-SA 4.0; wordfreq CC BY-SA 4.0;
   kfxlib, WordDumb/Proficiency, kfxgen, kindle-cli). Empty state mentions X-Ray and Word Wise.
2. **Bundle config.** Copyright, category Productivity, short/long description, macOS minimum
   14.0, NSIS per-user install (no admin), `.dmg` + `.app` + `.exe` + `.msi`. Unit test that the
   config keeps `minimumSystemVersion` and the CSP.
3. **Release workflow** `.github/workflows/release.yml`: on a `v*` tag (and manual dispatch),
   build macOS arm64 + x86_64 and Windows x64 with `tauri-action`, sign/notarize when the secrets
   exist, attach to a **draft** release. The owner publishes the draft.
4. **README**: install (Mac: Gatekeeper note until signed; Windows: SmartScreen note), first run,
   privacy / network list, the research write-up (what store-quality sideloading needs and how
   Deckle gets each piece), build from source, credits. `CHANGELOG.md` with 0.1.0.
5. **Verify**: `pnpm tauri build` locally → `.app` and `.dmg`; launch the bundled app, screenshot
   the About section; CI green.
6. **Tag `v0.1.0`** (owner's go-ahead): pushes the tag, the workflow builds the draft release.

## Owner-only

- Developer ID Application certificate + app-specific password → repository secrets (runbook in
  `docs/release.md`).
- Windows code-signing certificate (a purchase; v1 ships unsigned per §12).
- Device verification of M1–M4 (`docs/devices.md`).
