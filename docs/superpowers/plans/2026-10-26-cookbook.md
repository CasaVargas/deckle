# The Kitchen Book (cookbook) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Saved recipe links become one Kindle book: a cookbook filed into chapters with
pictures and an ingredient index, kept as plain files, rebuilt on change and delivered to every
Kindle on its next plug-in.

**Architecture:** A new module `deckle_digest::cookbook` (under
`crates/deckle-digest/src/cookbook/`) holds the recipe parser (schema.org JSON-LD, with the
article extractor as fallback), the file store, chapter filing, the ingredient index, pictures
and the EPUB writer. `deckle-cli` gets `deckle cookbook …`, the build-and-prepare step (Kindle
Previewer, through the existing `pipeline::prepare`), and a standing per-Kindle delivery that
plugs into `digest watch` and `digest push` through the existing outbox. The desktop tab is
the last part, and it starts only after the Daily redesign has merged.

**Tech Stack:** Rust 2024 workspace; `serde_json` (JSON-LD), `dom_query` (script tags),
`image` (crop), `toml_edit` (comment-keeping config), the crate's `epub::write`,
`render::Files`, `cover` canvas and `article` helpers; `deckle-core` `pipeline::prepare`,
`queue::Queue`; Tauri 2 + React/TS with vitest for Part 6.

**Spec:** `docs/superpowers/specs/2026-10-26-cookbook-design.md`. Section numbers (§) below
refer to it.

## Global Constraints

- **One PR per Part.** Parts 1–5 are Rust only. **Part 6 (desktop) starts only after #206,
  #207 and #208 have merged into `main`.** Re-read `apps/desktop/src/DailyView.tsx`,
  `saveQueue.ts` and the Daily redesign spec on `main` before starting it.
- Book identifier: `urn:deckle:cookbook:default`, exactly, every build (§6.1).
- Device file name: `Deckle Kitchen Book.kfx`, exactly, whatever the title. It goes through
  the existing `Prepared.name` field (`crates/deckle-core/src/pipeline.rs:209`, "The device
  file name; `None` uses `<Author sort> - <Title>.kfx`"). **Correction to spec §6.1:** this
  override already exists, so no change to `deliver` is needed.
- Store root: `cookbook/` beside `digest.toml` (`deckle_digest::config::default_path()`'s
  parent), overridable by `DECKLE_COOKBOOK_DIR` for tests, as `DECKLE_READING_QUEUE` does
  for the reading queue.
- Recipe id: `format!("{:012x}", fnv(&normalize_url(url)) >> 16)`, which is 12 hex digits,
  using `reading::fnv` and `reading::normalize_url`. For a saved page, use its canonicalized
  absolute path in place of the URL (§5).
- `build` makes **no network calls**: it takes no `Net`, and nothing it calls fetches. Code that fetches (`add`, `preview`, `scan_recipes`) is tested with a fixture `Net`, and `saved_page_never_fetches` uses one that panics.
- **No X-Ray and no Word Wise** on the cookbook: `XRayMode::Off`, `word_wise: None` (§9).
- Pictures: center-crop to 3:2, then `article::eink_photo`, so ≤ 1000 px wide and grayscale
  (§7.1, corrected).
- Illustrations: nothing is ever sent unless `[illustrations] enabled = true`. The request
  body has only the title, the chapter name and ≤ 8 ingredient keys (§7.2).
- Copy (sentence case, as written in the spec): "Read from the page text, not recipe data",
  "No picture on the page", "Couldn't draw this one; kept the photo",
  "Illustration generated", "Updated", "Added to *<chapter>*".
- Fixtures are fictional recipes written for the tests, never copied from real sites (§10).
- Tests: run the focused test target per task (`cargo test -p deckle-digest --test
  cookbook_<name>`). Run the full workspace suite once per Part, before its PR. The shared
  cargo target makes repeated full runs slow.
- Conventional commits; each Part's PR body says `Part N of docs/superpowers/plans/2026-10-26-cookbook.md`.

## Review Focus

1. **A food blog with two Recipe nodes, or a Recipe nested in `@graph` next to a WebPage
   whose `name` is the blog's title.** The parser must take the Recipe node's `name`, not
   the page's. Test: `two_recipe_nodes_takes_first_complete` and
   `graph_recipe_ignores_webpage_name` (Task 1.1).
2. **Re-saving a recipe the owner moved, renamed and annotated.** The chapter, title
   override, note and picture choice survive, and parsed fields refresh. Test:
   `resave_keeps_owner_fields` (Task 1.3).
3. **A Kindle unplugged mid-push, then a different Kindle plugged in.** The second Kindle's
   owned entry replaces the first's queued one (same queue name). The first Kindle still gets
   the book on its next plug-in, because its `delivered.json` record never advanced. Test:
   `interrupted_push_redelivers_later` (Task 3.3).
4. **Renaming the book in `cookbook.toml` between builds.** Still one file on the Kindle,
   because the device name is fixed. Test: `rename_keeps_one_device_file` (Task 3.3).
5. **An ingredient line that reduces to nothing** ("Salt and pepper, to taste", "2 (14 oz)
   cans", "For the dressing:"). No index key, and no empty or junk entry. Test:
   `key_ingredient_rejects_junk` (Task 2.1).
