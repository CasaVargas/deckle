# Weather, Almanac and Your Day Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the paper's Weather section into a **Weather & Almanac** page: five-day strip,
locally computed sun, moon, seasons and meteor showers, a cached frost line, and **Your Day**
from `.ics` calendars with a rain note.

**Architecture:**
- Pure, I/O-free modules in `crates/deckle-digest/src/` (`tz`, `sun`, `moon`, `seasons`,
  `showers`, `frost`, `day`) compute each part.
- `sources/weather.rs` fetches the forecast, reads the frost cache and calendars, and passes
  everything to a pure `page()` function. `page()` assembles one `Section` and degrades per
  part.
- Icons are PNG assets the EPUB writer embeds.
- The desktop Daily tab gains a Your Day card over the existing `daily_save`.

**Tech Stack:**
- Rust 2024 workspace. New crates: `chrono-tz`, `iana-time-zone`, `icalendar` (`parser`
  feature) and `rrule`.
- Tauri 2 and React/TS with vitest.

**Spec:** `docs/superpowers/specs/2026-10-22-almanac-design.md`

## Global Constraints

- Section config name and readership key stay `weather`; title becomes `Weather & Almanac`.
- "Today" is the edition date in the Mac's local zone (`tz::local_tz()`); every pure function
  takes `tz: chrono_tz::Tz` explicitly so tests never depend on the machine.
- Units: imperial → °F, mph, 12-hour `7:28 AM`; metric → °C, km/h, 24-hour `19:28`.
- Network: only the existing Open-Meteo forecast call (now with `hourly=`), the one-time
  archive call, and calendar addresses, all through `Net`.
- Calendar contents are never logged or cached; a calendar address appears in any message only
  as `mask()` output (`https://host/…`).
- `CLASS:PRIVATE`/`CLASS:CONFIDENTIAL` → title `Busy`; never named in the weather note.
- Accuracy: sunrise/sunset within 2 min of USNO; full/new moon on the correct local date;
  equinox/solstice within 5 min.
- Every icon has its word next to it; icons are grayscale PNGs with `alt=""`.
- Footer copy, exact: `Forecast: Open-Meteo · Sky and moon worked out on your Mac`.
- Pre-push hook runs `cargo fmt --check` and clippy `-D warnings`; keep both clean per commit.

**Plan rulings** (decisions the spec left open; flagged to the owner):

- **TZID handling:** IANA names are honoured. Windows names, as Outlook writes them, are mapped
  through a fixed table (`day::WINDOWS_ZONES`, §Task 7). Any other `TZID` is treated as the
  local zone, and the agenda adds a note: "Some times shown in local time". Full `VTIMEZONE`
  rule evaluation is not built.
- **Shower latitude skip:** the spec's rule (`dec < lat − 90°`) only ever triggers at the
  poles. The plan uses "the radiant never climbs 10° above the horizon" instead: `dec < lat −
  80°` in the north, `dec > lat + 80°` in the south. This keeps the spec's intent.
- **Reference data:** the expected values in sun, moon and season tests are fetched once from
  USNO's public API by the executor and committed as fixtures (Tasks 1–3). No hand-typed
  astronomy.

## Review Focus

1. **Calendar on a clock-change day.** A 9:00 weekly event (`TZID=America/New_York`) on
   2026-11-01 still prints 9:00 AM. Test in Task 7.
2. **A webcal address that returns an HTML login page** (an expired secret link). This is a
   per-calendar error with the masked address, and the rest of the page still prints. Test in
   Task 7.
3. **A machine whose zone differs from the forecast location** (a laptop travelling). Hourly
   times are taken as the location's local time, and the rain note's hour matches the
   forecast's own clock. Test in Task 8.
4. **Year wrap.** The Quadrantids (Dec 28–Jan 12) show on Dec 30 and Jan 2. The frost window
   works across Jan 1 in the southern hemisphere. Tests in Tasks 4 and 5.
5. **A frost cache from an old location.** After the user moves, a cache keyed to the old
   lat/lon is ignored and a new fetch is made, not the old value. Test in Task 5.
