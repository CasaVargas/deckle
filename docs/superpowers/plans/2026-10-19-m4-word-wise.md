# M4: Word Wise — Implementation Plan

**Goal:** Every EBOK book Deckle sends gets a Word Wise sidecar: short hints above hard words,
at KFX positions, filtered by the user's hint level. Data is Deckle's own Wiktionary-derived
database, built offline by `data/wordwise` and downloaded on first use. No LLM, no Amazon data
shipped.

**Spec:** design §4.5 (Word Wise), §9 (Word Wise data pipeline), §2 anti-goals (no Amazon data).

## Facts (from WordDumb d89c105 and Proficiency ee238a5, both GPL-3)

- Sidecar: `<book>.sdr/LanguageLayer.en.<ASIN>.kll`, SQLite, two tables:
  `metadata(key TEXT, value TEXT)` and
  `glosses(start INTEGER PRIMARY KEY, end INTEGER, difficulty INTEGER, sense_id INTEGER,
  low_confidence BOOLEAN)`. Metadata rows: `acr` (KFX asset id), `targetLanguages en`,
  `sidecarRevision 9`, `bookRevision` (empty for KFX), `sourceLanguage en`,
  `enDictionaryVersion`, `enDictionaryRevision 57`, `enDictionaryId`, `sidecarFormat 1.0`.
  `start` = KFX position (run pid + code-point offset, same model as X-Ray); `end` is NULL for a
  single word and the end position for a phrase. Requires EBOK + matching ASIN, like X-Ray.
- **The `.kll` holds no text.** `sense_id` points into a dictionary on the device,
  `system/kll/kll.<book lang>.<gloss lang>.klld` (SQLite: `lemmas`, `senses` with base64
  `short_def`/`full_def`/`example_sentence`, `pos_types`, `sources`, `metadata`). The Kindle
  picks the `.klld` from its Word Wise *language* setting.
- `kll.en.en.klld` is Amazon's dictionary, downloaded by the Kindle the first time Word Wise is
  used on a registered device. Store books' sidecars point into it, so overwriting it breaks
  them. WordDumb's Wiktionary mode instead writes its dictionary into the `kll.en.zh.klld` slot
  and tells the user to set Word Wise language to Chinese (the glosses themselves are English).
- Difficulty 1–5: 1 = rarest (shown even at "fewer hints"), 5 = commonest (shown only at "more
  hints"). Proficiency maps wordfreq Zipf to it; Amazon's own list enables ~40k lemmas.

## Decisions

1. **Two dictionary modes, chosen per device, automatically.**
   - **Device dictionary** (preferred, zero-config): the Kindle has `kll.en.en.klld`. Deckle
     reads it from the device at send time (never stores or ships it) and resolves each of its
     own matched lemmas + POS to Amazon's sense id. Hints look exactly like store books'.
   - **Deckle dictionary** (fallback): no `kll.en.en.klld`, or its schema is not what we expect.
     Deckle writes its own `.klld` to `system/kll/kll.en.zh.klld` **only if that slot is empty or
     already Deckle's** (metadata `deckleDictionary` row), and the result line says "Word Wise:
     set the Kindle's Word Wise language to 中文 once (Deckle dictionary)". If the slot holds
     Amazon's Chinese dictionary, Word Wise is withheld with that reason; never clobbered.
   - **Folder export**: Deckle dictionary; the `.klld` goes to `<out>/system/kll/kll.en.zh.klld`
     so a manual copy mirrors the device layout.
2. **Deckle's database** (`deckle-wordwise-en-v1.sqlite`, downloaded, sha256-pinned, cached in the
   app data dir): `metadata`, `senses(id, lemma, pos, short_def, full_def, example,
   difficulty)`, `forms(form, sense_id)` with one precomputed best sense per surface form, so the
   app needs no lemmatizer or POS tagger. The app derives the `.klld` from it and caches that too.
3. **Difficulty** from wordfreq `large_en` (CC BY-SA 4.0) Zipf (bands revised during execution,
   see below). Wiktionary POS kept: noun, verb, adj,
   adv, phrase. Senses tagged obsolete/archaic-only form-of/alt-of/misspelling/abbreviation dropped.
4. **Matching** (`deckle-wordwise::matcher`): tokenize each run (letters, inner `'`/`-`),
   longest phrase first (3, 2, 1 tokens) against `forms`, case-insensitive; a capitalized word
   mid-sentence is a proper noun and is skipped; one gloss per occurrence. Hint level *L* writes
   senses with difficulty ≤ *L*; the Kindle's own slider then filters further. Default **5**
   (let the device slider decide).
5. **Download** from this repo's GitHub Releases (`wordwise-v1` tag), the fourth network call
   Deckle makes; it happens only when Word Wise is on and the DB is not cached, is reported in
   the result line, and `--wordwise-db <path>` / `DECKLE_WORDWISE_DB` point at a local file
   instead. Word Wise defaults **on** (the download is data, not a per-book lookup); a failed
   download is a warning, never a failed run.

## Tasks (TDD each; commit per task)

1. `crates/deckle-wordwise`: `db` (schema, open, `Lexicon` = forms → (sense, lemma, pos,
   difficulty)), `kll::write(path, &LanguageLayer)` exact schema, `klld::write_from_db`.
   Tests read back with rusqlite.
2. `deckle-wordwise::matcher::glosses(runs, &Lexicon, level) -> Vec<Gloss{start, end,
   difficulty, sense}>`: phrases, proper-noun skip, positions in code points. Fixture lexicon.
3. `data/wordwise` bin (`deckle-wordwise-build`): kaikki JSONL(.gz) + wordfreq msgpack →
   database. Unit-tested on a 20-entry JSONL sample; checked into `fixtures/wordwise/` as the
   test DB. Real build run locally; size and counts recorded in `docs/formats/wordwise.md`.
4. `deckle-wordwise::device`: read an Amazon-shaped `.klld` → map (lemma, pos) → sense id, with a
   schema probe. Tested on a synthetic Amazon-shaped klld.
5. Core: `deckle-core::wordwise` stage (mode choice, sidecar + optional klld), download-on-first-
   use with injectable fetch + sha256; mass storage reads/writes `system/kll`; MTP gets
   `get_object` and a path walk; `DeliverOptions.system_files`. Report `word_wise: {hints,
   level, dictionary}`; stale `LanguageLayer.*.kll` removed on re-send.
6. CLI `--word-wise off|auto`, `--word-wise-level 1-5`, `--wordwise-db`; GUI: settings drawer
   toggle + level live, result line `Word Wise: 1,204 hints (level 5, device dictionary)`.
7. Docs: `docs/formats/wordwise.md`, README, device runbook (Paperwhite: hints appear; Scribe).
   Credits: Wiktionary CC BY-SA 3.0/4.0, wordfreq CC BY-SA 4.0, WordDumb/Proficiency.

## Out of scope for M4

Non-English books (the pipeline is language-parameterized but only `en` is built), POS tagging,
per-word user overrides, Anki/Vocabulary Builder import.

## Deviations recorded during execution

- Difficulty bands: Proficiency's (≥ 5 off, 4.x → 5 …) hinted 20 % of Pride and Prejudice
  ("sister", "letter", "evening"); now ≥ 4.25 off, 3.75 / 3.25 / 2.75 / 2.0 band edges: 9 %.
- Proper nouns are learned per book (capitalized mid-sentence more than lowercase) and "Mr." does
  not end a sentence: "Darcy" (a permeability unit) and "Bennet" (a plant) were hinted.
- A surface form maps to the entry with the most senses before its own lemma ("ladies" was a
  poker hand); the everyday sense beats archaic and specialist ones; dated spellings are hinted
  with the modern word; examples are not stored (dictionary 57 → 40 MB, download 18 → 12 MB).
- The database carries a `build` fingerprint: a rebuilt database with the same version reused a
  stale cached `.klld`, which would have pointed sidecars at the wrong senses on the device.
- The hint level defaults to 5 (was a placeholder 3 in the M1b GUI), Word Wise defaults on.
- Spotted while verifying: the embedded (non-dev) desktop build's CSP blocked `data:` cover
  thumbnails; `img-src 'self' data:` added.
- The database release asset (`wordwise-v1`) is not published by this PR; until it is, a fresh
  install reports "Word Wise skipped: could not download …" and ships the book without it.
