# M3: X-Ray — Implementation Plan

**Goal:** Every EBOK book Deckle sends gets an X-Ray sidecar: people and terms, spoiler-free
descriptions, occurrences at KFX positions. LLM-written when a provider is configured, heuristic
plus optional Wikipedia otherwise. "X-Ray: basic" is the accepted no-network result.

**Spec:** design §4.5 (X-Ray), §7 (LLM policy), §9 (entity-to-position mapping).

**Facts (from WordDumb, GPL-3, and kfxlib):**
- File: `<book>.sdr/XRAY.entities.<ASIN>.asc`, SQLite, `PRAGMA user_version=1`, tables
  `book_metadata, entity, entity_description, entity_excerpt, excerpt, occurrence, source,
  string, type`; fixed rows `entity(0, loc_label 1, has_info_card 0)`, `source 0/1/2`,
  `type 1=People(14/15) 2=Terms(16/17)` with `top_mentioned_entities` = top-10 ids by count,
  indices on entity.type, entity_excerpt.entity, occurrence.start; `book_metadata(srl 0, erl,
  has_images, has_excerpts 0, show_spoilers_default 0, num_people, num_terms, num_images,
  preview_images)`. Strings table from WordDumb's `x_ray_strings.json` (ids 0..20, 1000, 1001)
  plus 21 = Wikipedia URL template, 22 = MediaWiki URL template.
- Positions: KFX json-content lists text runs `{position: pid, content}`; occurrence `start` =
  run pid + character (code point) offset; `erl` = last run's pid + len(content). Deckle's
  `$265`/storyline-text runs are the same thing (page-number parity proved it).
- Requires the book be EBOK with the same ASIN as the sidecar name.

## Tasks (TDD each; commit per task)
1. `deckle-kfx::text::content_runs(kfx) -> (Vec<Run{pid, text}>, erl)` from a monolithic KFX.
2. `crates/deckle-xray`: `asc::write(path, &XRayBook)` with the exact schema; test by reading back
   with rusqlite (row counts, types, indices, strings).
3. `deckle-xray::extract::heuristic(runs, lang) -> Vec<Candidate>`: capitalized n-grams, stop
   lists, honorifics, sentence-start discounting, alias merge (surname ⊂ full name), min count 2,
   person/term classification, first-mention quote. Tested on Pride and Prejudice (Elizabeth,
   Darcy, Bingley, Jane, Netherfield, Longbourn present; "The", "Chapter" absent).
4. `deckle-xray::llm`: `Describer` over an injectable HTTP fn; Anthropic Messages and
   OpenAI-compatible chat providers; prompt asks for JSON `[{name, kind, description, aliases}]`
   (spoiler-free, 1–2 sentences); robust JSON extraction; keys from env
   `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`. Tested with canned responses.
5. `deckle-xray::wiki`: summary via `https://<lang>.wikipedia.org/api/rest_v1/page/summary/<title>`,
   injectable fetch, opt-in.
6. Pipeline `enrich` stage: on EBOK, build the sidecar (LLM → wiki → quote fallback), deliver into
   `<book>.sdr/` on mass storage and MTP (`DeliverOptions.sidecars`); report `xray: {people,
   terms, source}`. CLI `--xray off|auto`, `--llm off|anthropic|openai`; settings + GUI result line.
7. Docs: formats/xray.md, README, devices runbook (verify on the Paperwhite: X-Ray opens).
